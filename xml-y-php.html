    5. XML y PHP

    En este capítulo, ofreceremos una introducción al uso de documentos XML (eXtensible Markup Language) con PHP. Lo haremos en el contexto de la aplicación fiscal tratada en el capítulo anterior.

    5.1. Archivos XML y hojas de estilo XSL

    Consideremos el siguiente archivo XML, que podría representar los resultados de simulaciones:

    <?xml version="1.0" encoding="windows-1252"?>
<simulations>
  <simulation marie="oui" enfants="2" salaire="200000" impot="22504"/>
  <simulation marie="non" enfants="2" salaire="200000" impot="33388"/>
</simulations>

    Al visualizarlo con IE 6, se obtiene el siguiente resultado:

    IE6 reconoce que se trata de un archivo XML (gracias a la extensión .xml del archivo) y lo formatea a su manera. Con Netscape, aparece una página en blanco. Sin embargo, si se consulta el código fuente (Ver/Fuente), se puede ver el archivo XML original:

    ¿Por qué Netscape no muestra nada? Porque necesita una hoja de estilo que le indique cómo transformar el archivo XML en un archivo HTML que luego pueda mostrar. Resulta que IE 6 tiene una hoja de estilo predeterminada cuando el archivo XML no proporciona una, que era el caso aquí.

    Existe un lenguaje llamado XSL (eXtensible StyleSheet Language) que permite describir las transformaciones necesarias para convertir un archivo XML en cualquier archivo de texto. XSL admite numerosas instrucciones y se asemeja mucho a los lenguajes de programación. No entraremos en detalles aquí, ya que eso requeriría docenas de páginas. Nos limitaremos a describir dos ejemplos de hojas de estilo XSL. El primero es el que transformará el archivo XML simulations.xml en código HTML. Modificamos este último para que especifique la hoja de estilo que los navegadores pueden utilizar para transformarlo en un documento HTML que puedan mostrar:

    <?xml version="1.0" encoding="windows-1252"?>
<?xml-stylesheet type="text/xsl" href="simulations.xsl"?>
<simulations>
  <simulation marie="oui" enfants="2" salaire="200000" impot="22504"/>
  <simulation marie="non" enfants="2" salaire="200000" impot="33388"/>
</simulations>

    El comando XML

    <?xml-stylesheet type="text/xsl" href="simulations.xsl"?>

    designa el archivo simulations.xsl como una hoja de estilo XML de tipo text/xsl, es decir, un archivo de texto que contiene código XSL. Los navegadores utilizarán esta hoja de estilo para transformar el texto XML en un documento HTML. Este es el resultado obtenido con Netscape 7 al cargar el archivo XML simulations.xml:

    Cuando vemos el código fuente del documento (Ver/Fuente), vemos el documento XML original en lugar del documento HTML mostrado:

    • Una hoja de estilo XSL es un archivo XML y, por lo tanto, sigue las reglas de XML. Entre otras cosas, debe estar «bien formada», lo que significa que todas las etiquetas de apertura deben cerrarse.
    • El archivo comienza con dos directivas XML que se pueden incluir en cualquier hoja de estilo XSL en Windows: 
    <?xml version="1.0" encoding="windows-1252"?>
  <xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">

    El atributo «encoding="windows-1252"» permite utilizar caracteres acentuados en la hoja de estilo.

    • La etiqueta <xsl:output method="html" indent="yes"/> indica al intérprete XSL que queremos generar HTML «sangrado».
    • La etiqueta <xsl:template match="element"> se utiliza para definir el elemento del documento XML al que se aplicarán las instrucciones que se encuentran entre <xsl:template ...> y </xsl:template>. 
        <xsl:template match="/">
................
        </xsl:template>

    En el ejemplo anterior, el elemento «/» hace referencia a la raíz del documento. Esto significa que, tan pronto como se encuentre el inicio del documento XML, se ejecutarán los comandos XSL situados entre las dos etiquetas.

    • Todo lo que no sea una etiqueta XSL se incluye tal cual en el flujo de salida. Las propias etiquetas XSL se ejecutan. Algunas de ellas producen un resultado en el flujo de salida. Examinemos el siguiente ejemplo: 
        <xsl:template match="/">
        <html>
          <head>
            <title>Simulations de calculs d'impôts</title>
        </head>
          <body>
            <center>
              <h3>Simulations de calculs d'impôts</h3>
            <hr/>
            <table border="1">
                    <th>marié</th><th>enfants</th><th>salaire</th><th>impôt</th>
                          <xsl:apply-templates select="/simulations/simulation"/>
                        </table>
          </center>
        </body>
      </html>
        </xsl:template>

    Tenga en cuenta que el documento XML que se está analizando es el siguiente:

    <?xml version="1.0" encoding="windows-1252"?>
<simulations>
  <simulation marie="oui" enfants="2" salaire="200000" impot="22504"/>
  <simulation marie="non" enfants="2" salaire="200000" impot="33388"/>
</simulations>

    Desde el inicio del documento XML analizado (match="/"), el procesador XSL generará el texto

    <html>
          <head>
            <title>Simulations de calculs d'impôts</title>
        </head>
          <body>
            <center>
              <h3>Simulations de calculs d'impôts</h3>
            <hr>
            <table border="1">
                    <th>marié</th><th>enfants</th><th>salaire</th><th>impôt</th>

    Ten en cuenta que en el texto original teníamos <hr/> y no <hr>. En el texto original, no podíamos escribir <hr> porque, aunque es una etiqueta HTML válida, es una etiqueta XML inválida. Sin embargo, aquí estamos trabajando con texto XML que debe estar «bien formado», lo que significa que todas las etiquetas deben estar cerradas. Por lo tanto, escribimos <hr/>, y como hemos escrito <xsl:output text="html ...> el intérprete transformará el texto <hr/> en <hr>. A continuación de este texto aparecerá el texto generado por el comando XSL:

          <xsl:apply-templates select="/simulations/simulation"/>

    Más adelante veremos qué es este texto. Por último, el intérprete añadirá el texto:

                        </table>
          </center>
        </body>
      </html>

    El comando <xsl:apply-templates select="/simulations/simulation"/> indica al intérprete que aplique la «plantilla» al elemento /simulations/simulation. Se ejecutará cada vez que el intérprete XSL encuentre una etiqueta <simulation>..</simulations> o <simulation/> dentro de una etiqueta <simulations>..</simulations> en el texto XML analizado. Al encontrar dicha etiqueta, el intérprete ejecutará las instrucciones de la siguiente plantilla:

        <xsl:template match="simulation">
          <tr>
            <td><xsl:value-of select="@marie"/></td>
            <td><xsl:value-of select="@enfants"/></td>
            <td><xsl:value-of select="@salaire"/></td>
            <td><xsl:value-of select="@impot"/></td>
        </tr>
       </xsl:template>

    Considere las siguientes líneas XML:

    <simulations>
  <simulation marie="oui" enfants="2" salaire="200000" impot="22504"/>

    La línea <simulación ..> corresponde a la plantilla para la instrucción XSL <xsl:apply-templates select="/simulaciones/simulación">. Por lo tanto, el intérprete XSL intentará aplicar las instrucciones que coincidan con esta plantilla. Encontrará la plantilla <xsl:template match="simulación"> y la ejecutará. Recordemos que todo lo que no sea un comando XSL pasa sin cambios por el intérprete XSL, mientras que los comandos XSL se sustituyen por el resultado de su ejecución. La instrucción XSL <xsl:value-of select="@champ"/> se sustituye así por el valor del atributo «champ» del nodo analizado (en este caso, un nodo <simulation>). El análisis de la línea XML anterior producirá el siguiente resultado:

    5.2. Aplicación fiscal: Versión 5

    5.2.1. Los archivos XML y las hojas de estilo XSL de la aplicación fiscal

    Volvamos a nuestro punto de partida, que era la aplicación web de impuestos, y recordemos que queremos modificarla para que la respuesta enviada a los clientes esté en formato XML en lugar de HTML. Esta respuesta HTML irá acompañada de una hoja de estilo XSL para que los navegadores puedan mostrarla. En el párrafo anterior, presentamos:

    • el archivo simulations.xml, que es un prototipo de respuesta XML que contiene simulaciones de cálculo de impuestos
    • el archivo simulations.xsl, que será la hoja de estilo XSL que acompañará a esta respuesta XML

    También debemos tener en cuenta el caso de una respuesta que contenga errores. El prototipo de la respuesta XML en este caso será el siguiente archivo errors.xml:

    <?xml version="1.0" encoding="windows-1252"?>
<?xml-stylesheet type="text/xsl" href="erreurs.xsl"?>
<erreurs>
    <erreur>erreur 1</erreur>
  <erreur>erreur 2</erreur>
</erreurs>

    La hoja de estilo errors.xsl utilizada para mostrar este documento XML en un navegador será la siguiente:

    <?xml version="1.0" encoding="windows-1252"?>
  <xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
      <xsl:output method="html" indent="yes"/>

    <xsl:template match="/">
        <html>
          <head>
            <title>Simulations de calculs d'impôts</title>
        </head>
          <body>
            <center>
              <h3>Simulations de calculs d'impôts</h3>
          </center>            
          <hr/>
          Les erreurs suivantes se sont produites :
          <ul>
                  <xsl:apply-templates select="/erreurs/erreur"/>
              </ul>            
        </body>
      </html>
        </xsl:template>

    <xsl:template match="erreur">
          <li><xsl:value-of select="."/></li>
        </xsl:template>
</xsl:stylesheet>

    Esta hoja de estilo introduce un comando XSL que aún no se ha visto: <xsl:value-of select="."/>. Este comando devuelve el valor del nodo analizado, en este caso un nodo <error>text</error>. El valor de este nodo es el texto que se encuentra entre las etiquetas de apertura y cierre, en este caso «text».

    El código errors.xml se transforma mediante la hoja de estilo errors.xsl en el siguiente documento HTML:

    <html>
<head>
<title>Simulations de calculs d'impots</title>
</head>
<body>
<center>
<h3>Simulations de calculs d'impots</h3>
</center>
<hr>
          Les erreurs suivantes se sont produites :
          <ul>
<li>erreur 1</li>
<li>erreur 2</li>
</ul>
</body>
</html>

    • La función startElement($parser, $name, $attributes) se invoca al inicio de cada etiqueta.
      • añade la etiqueta $name a una matriz de etiquetas $tags. Esta matriz se gestiona como una pila: al encontrar el símbolo de fin de etiqueta, se extrae la última etiqueta insertada en $tags. En este caso, la documentación de PHP no menciona esta restricción. Como precaución, almacenamos el valor $data obtenido en una variable global $content.     • La función endElement($parser, $name) se invoca al final de cada etiqueta. Aquí se utiliza para cambiar el nombre de la etiqueta actual eliminando la última etiqueta de la pila de etiquetas y para añadir el contenido de la etiqueta de cierre <error> a la matriz $impots[errors].

    5.5. Conclusión

    Gracias a su respuesta XML, la aplicación fiscal se ha vuelto más fácil de gestionar tanto para su desarrollador como para los desarrolladores de aplicaciones cliente.

    • El diseño de la aplicación de servidor puede ahora confiarse a dos tipos de personas: el desarrollador PHP del servlet y el diseñador gráfico que se encargará de la apariencia de la respuesta en los navegadores. Este último solo necesita conocer la estructura de la respuesta XML del servidor para crear las hojas de estilo que la acompañarán. Tenga en cuenta que estas se encuentran en archivos XSL separados, independientes de la aplicación PHP. El diseñador de la interfaz de usuario puede, por lo tanto, trabajar de forma independiente del desarrollador.
    • Los diseñadores de aplicaciones cliente, también, solo necesitan conocer la estructura de la respuesta XML del servidor. Cualquier cambio que el diseñador front-end pueda realizar en las hojas de estilo no tiene ningún impacto en esta respuesta XML, que siempre permanece igual. Esto supone una gran ventaja.
    • ¿Cómo puede el desarrollador actualizar su aplicación PHP sin estropearlo todo? En primer lugar, siempre que la respuesta XML permanezca sin cambios, puede organizar su aplicación como desee. También puede actualizar la respuesta XML siempre que conserve los elementos <error> y <simulation> que esperan sus clientes. De este modo, puede añadir nuevas etiquetas a esta respuesta. El desarrollador front-end las tendrá en cuenta en sus hojas de estilo, y los navegadores podrán mostrar la versión actualizada de la respuesta. Los clientes programáticos, sin embargo, seguirán funcionando con el modelo antiguo, ignorando simplemente las nuevas etiquetas. Para que esto funcione, las etiquetas que se buscan deben identificarse claramente en el análisis XML de la respuesta del servidor. Esto es lo que se hizo en nuestro cliente XML para la aplicación fiscal, donde los procedimientos indicaban específicamente que estábamos procesando las etiquetas <error> y <simulation>. Como resultado, se ignoran las demás etiquetas.

    8.1. Herramientas de desarrollo web

    Aquí indicamos dónde encontrar y cómo instalar las herramientas necesarias para el desarrollo web. Algunas herramientas han visto evolucionar sus versiones, y es posible que las explicaciones proporcionadas aquí ya no se apliquen a las versiones más recientes. El lector deberá entonces adaptarse... En el curso de programación web, utilizaremos principalmente las siguientes herramientas, todas ellas disponibles de forma gratuita:

    • un navegador reciente capaz de mostrar XML. Los ejemplos del curso se han probado con Internet Explorer 6.
    • Un JDK (Java Development Kit) reciente. Los ejemplos de este curso se han probado con el JDK 1.4. Este JDK incluye el complemento de navegador Java 1.4, que permite a los navegadores mostrar applets de Java utilizando el JDK 1.4.
    • Un entorno de desarrollo Java para escribir servlets Java. En este caso, se trata de JBuilder 7.
    • Servidores web: Apache, PWS (Personal Web Server), Tomcat.
      • Se utilizará Apache para desarrollar aplicaciones web en PERL (Practical Extracting and Reporting Language) o PHP (Personal Home Page).
      • Se utilizará PWS para desarrollar aplicaciones web en ASP (Active Server Pages) o PHP
      • Tomcat se utilizará para desarrollar aplicaciones web utilizando servlets Java o JSP (Java Server Pages).
    • Una aplicación de gestión de bases de datos: MySQL
    • EasyPHP: una herramienta que integra el servidor web Apache, el lenguaje PHP y el SGBD MySQL

    8.1.3. EasyPHP

    Esta aplicación es muy práctica porque incluye lo siguiente en un solo paquete:

    • el servidor web Apache (1.3.x)
    • el lenguaje PHP (4.x)
    • el SGBD MySQL (3.23.x)
    • una herramienta de administración de MySQL: PhpMyAdmin

    La aplicación de instalación tiene este aspecto:

    La instalación de EasyPHP es sencilla y se crea una estructura de directorios en el sistema de archivos:

    el ejecutable de la aplicación

    8.1.6. VBScript, JavaScript, PerlScript

    Estos son lenguajes de scripting para Windows. Pueden ejecutarse en diversos entornos, tales como

    • Windows Scripting Host para su uso directo en Windows, especialmente para escribir scripts de administración del sistema
    • Internet Explorer. Se utiliza entonces dentro de páginas HTML, a las que añade un nivel de interactividad que no se puede lograr solo con HTML.
    • Internet Information Server (IIS), el servidor web de Microsoft en NT/2000, y su equivalente, Personal Web Server (PWS), en Win9x. En este caso, VBScript se utiliza para la programación web del lado del servidor, una tecnología denominada ASP (Active Server Pages) por Microsoft.

    • un intérprete de VBScript
    • un intérprete de JavaScript

    <job id="PERL1">
  <script language="PerlScript">
      # du Perl classique
    %dico=("maurice"=>"juliette","philippe"=>"marianne");

Incluso con esta restricción, esta opción sigue siendo útil, ya que, por lo general, resulta bastante poco práctico depurar scripts que se ejecutan en servidores web o navegadores.

    8.2.1. El cliente TCP genérico

    Muchos servicios creados en los albores de Internet funcionan según el modelo de servidor de eco estudiado anteriormente: la comunicación cliente-servidor se produce mediante el intercambio de líneas de texto. Escribiremos un cliente TCP genérico que se iniciará de la siguiente manera: java cltTCPgenerique servidor puerto

    Este cliente TCP se conectará al puerto port del servidor server. Una vez conectado, creará dos subprocesos:

    1. un subproceso encargado de leer los comandos tecleados en el teclado y enviarlos al servidor
    2. un subproceso encargado de leer las respuestas del servidor y mostrarlas en pantalla

    ¿Por qué dos subprocesos? Cada servicio TCP-IP tiene su propio protocolo específico, y a veces se dan las siguientes situaciones:

    • el cliente debe enviar varias líneas de texto antes de recibir una respuesta
    • la respuesta de un servidor puede contener varias líneas de texto

    Por lo tanto, el bucle que envía una sola línea al servidor y recibe una sola línea del servidor no siempre es adecuado. Por lo tanto, crearemos dos bucles separados:

    • un bucle para leer los comandos tecleados en el teclado que se enviarán al servidor. El usuario indicará el final de los comandos con la palabra clave «fin».
    • un bucle para recibir y mostrar las respuestas del servidor. Se tratará de un bucle infinito que solo se interrumpirá cuando el servidor cierre la conexión de red o cuando el usuario escriba el comando «end» en el teclado.

    Para tener estos dos bucles separados, necesitamos dos subprocesos independientes.       function transfert(L1,L2,simple){

        // index de l'élément sélectionné dans L1
        index1=L1.selectedIndex;

          return;

        if(simple){ // sélection simple
          element1=L1.options[index1].text;
          //ajout dans L2
          L2.options[L2.length]=new Option(element1);
          //suppression dans L1
          L1.options[index1]=null;

          for(i=L1.length-1;i>=0;i--){
